# 如何描述研究产物的可用性与许可证据

[English](artifact-evidence.md) · [中文贡献指南](../CONTRIBUTING.zh-CN.md) · [目录格式（英文）](../data/README.md)

论文和资源常常指向代码、数据、演示或基准，而它们的可用性和许可往往与粗看时不同。本页说明已有记录如何描述这些情形，让新记录沿用同样中立的措辞。关于可用性或许可的每一项说法，都要引用提出该说法的公开来源，并尽量固定到复核时的修订版本。

## 原则

- **能看到不等于获得许可。** 没有许可证文件的公开源码，没有写明任何复用条款。许可证文件、README 中的句子、软件包元数据和 GitHub 识别出的许可是彼此独立的信号，都不构成法律审查。
- **演示不等于基准。** 托管演示、展示页或评测服务，除非确实发布了可下载的数据集、基准或评测框架，否则不能当作它们。
- **只有作者提供的链接才算研究产物。** 论文的 `code_url` 和 `project_url` 是作者提供的链接。论文未链接的同名仓库不记为该论文的代码。
- **冲突要写明。** 来源之间说法不一致时，逐一注明各信号的来源，不要合并成一个标签。
- **区分版本。** 今天复核的仓库或之后的发布版本，除非作者明确说明，否则不是论文评测时使用的版本。
- **不越过访问限制。** 根据公开的访问说明描述访问条件；不要下载受限数据、代替项目方接受条款或运行代码。

论文的可用性记录在 `code_url` 和 `project_url` 中（没有符合条件的作者链接时为 `null`），并在 `metadata_notes` 与 `scope_limitations` 及对应的 `_zh` 字段中说明。资源的可用性写在 `requirements` 及其中文翻译中，许可证文件和软件包元数据以固定链接列入 `additional_evidence_urls`。

## 判断表

示例措辞取自已有记录的中文字段。

| 情形 | 应记录的内容 | 示例措辞 | 记录 |
| --- | --- | --- | --- |
| 作者链接了公开代码 | `code_url` 填作者提供的链接；注明复核的提交 | “论文直接链接至公开代码仓库。” | `paper-dashboard2code` |
| 源码公开但没有许可证文件 | 写明复用条款未声明；不因公开可见而推定许可 | “仓库没有许可证文件，因此不意味着授予任何复用许可。” | `paper-ble-automata-learning` |
| 代码已宣布或承诺发布 | `code_url: null`；注明公告及其出处 | “官方页面仍标注代码即将发布。” | `paper-sprite-game-ui` |
| 论文给出的位置并未提供代码 | `code_url: null`；写明该位置实际包含什么 | “因此 code_url 为 null，本条目不声称存在公开实现。” | `paper-dynpre` |
| 只有托管演示或展示页 | 该页面，说明它是演示而非基准发布 | “项目链接为含演示的展示页，不代表已核实发布完整评测框架。” | `paper-gamereplica` |
| 访问受限或需申请 | 公开的访问说明及其条件；不打开受限文件 | “链接的数据集需要接受访问条件并共享联系信息。” | `paper-dashboard2code` |
| 有仓库但作者未链接 | `code_url: null`；说明不记录该仓库的原因 | “论文也未链接它，因此不将其记录为作者提供的代码。” | `paper-binmetric` |
| 许可信号相互冲突 | 逐一列出各信号及来源；不宣称单一许可 | “许可信息存在冲突：README 正文声明 CC-BY-NC-SA-4.0，Hugging Face 元数据标为 Apache-2.0，项目页声明 CC BY-SA 4.0，setup.py 列出 MIT，但仓库没有 LICENSE 文件。因此不宣称产物适用统一许可。” | `paper-vision2web` |
| 许可只在一处声明 | 声明出现在哪里、哪些地方缺失 | “README 的 License 标题下写明 MIT，但固定提交中没有 LICENSE 文件，package.json 也没有 license 字段；该声明仅见于 README。” | `frida-mcp-yfe404` |
| 之后的产物版本与评测版本不同 | 你复核的版本及其差异 | “论文所用的 v1.00 原始数据仅可申请获取，公开的 v1.01 版本调整了数据划分” | `paper-exebench` |
| 无法确定评测所用版本 | 说明当前固定修订不被声称为历史版本 | “本次核查固定到当前提交，并不声称其仍与历史发布完全相同。” | `paper-pix2code` |

英文字段写同样的事实；[英文版指南](artifact-evidence.md)引用了这些记录的英文措辞。尚未解决的问题以明确的不确定说法留在记录中，并列出相互冲突的来源，而不是凭假设下结论。

## 仍有权利疑问时

有些资源带来证据无法解决的问题，例如项目自己说明提交的文件源自商业程序。请像上面一样在记录中中立地陈述事实，以草稿（draft）形式提交 pull request，并在开头向维护者说明顾虑。除项目自己的页面外，不要附加或链接有疑问的材料；仓库中绝不能包含专有二进制文件或私人抓包数据。
